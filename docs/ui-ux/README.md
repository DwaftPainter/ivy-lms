# IVY LMS UI/UX modernization

Phase 0 records how the current application is assembled, how representative screens render, and which flows need stronger evidence. Modernization should preserve the IVY identity and existing learning, teaching and administration workflows.

| Document | Use |
| --- | --- |

| [Component inventory](component-inventory.md) | Shared primitives, shell, feature owners, variants and dependencies. |

## Priorities for Phase 1

1. **Prioritize reachable assessment controls.** Reproduce builder clipping and measured overflow in the builder, exam, lesson and grading views. Check keyboard and touch access to the same actions before selecting changes. [Responsive evidence](baseline.md#confirmed-responsive-risks).
2. **Make shared navigation operable and predictable.** Start with the Admin mobile drawer focus return and unnamed header buttons. Compare the same controls in Student and Teacher, including notifications, route labels and keyboard access. [Browser evidence](baseline.md#browser-evidence).
3. **Reconcile evidenced foundation choices.** Establish which type, theme, focus and feedback patterns should govern shared surfaces. Check the actual calendar and role shells before normalizing primitives or tokens. Preserve the existing logo and brand red. [Design foundations](baseline.md#design-foundations).

The ten requested skills informed source tracing, evidence labeling, accessibility and motion checks, and component ownership. Phase 0 uses those review methods to prepare the audit. Design authoring and implementation are scheduled in later phases. [Roadmap](roadmap.md).
