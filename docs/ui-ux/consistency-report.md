# Cross-surface consistency

The Student, Teacher and Admin portals all compose SidebarProvider, AppSidebar and MainHeader. Their role destinations and page tasks differ. The [shared shell audit](audit/shared-shell.md) verifies common defects. [Route ownership](route-inventory.md#layouts-and-navigation) covers the intentional exam and Swagger exceptions.

| Pattern | Shared contract and divergence | Disposition |
| --- | --- | --- |
| Shell and navigation | Same sidebar/header and notification owner. Student/Teacher provide named route destinations. Admin's sidebar Dashboard entry is a hash and the surface heading owns orientation. Teacher full-width routes change their content margin. | Correct the reproduced Teacher active/title contradiction and shared mobile barriers. Keep route destinations and role-appropriate content width. [TCH-01](findings.md#tch-01), [SHELL-01](findings.md#shell-01), [SHELL-02](findings.md#shell-02). |
| Page headings and containers | Portal dash headings orient to the role. Student detail, Teacher lesson, management dialogs and graders use task-specific titles or widths. Student, Teacher and Admin have different inset spacing branches with the same header. | Test compact layouts against each task. An identical heading or container scale requires evidence and approval. [Student layout](../../src/app/%28student%29/layout.tsx), [Teacher layout](../../src/app/teacher/layout.tsx), [Admin layout](../../src/app/%28admin%29/admin/layout.tsx). |
| Cards and sections | Card provides shared grouped surfaces. Dashboards show upcoming work and counts; Admin management cards combine search and actions; the calendar and grader use feature composition. | Prefer existing Card semantics where they already govern. Preserve extra room and density on assessment workflows. [Card owner](../../src/components/ui/card.tsx). |
| Actions | Primary red anchors several default actions. Inline class overrides and separate task toolbars exist. Builder Save and grade draft actions require layout correction. | Restore reachability before deciding a broader hierarchy. [BLD-01](findings.md#bld-01), [GRD-01](findings.md#grd-01), [Button owner](../../src/components/ui/button.tsx). |
| Forms and dialogs | Auth uses Form/RHF and tied errors. Admin course editing uses local controlled fields and Radix Select. Grading uses paired Slider and number input. | Preserve the current field stack. Correct associations at unlabeled Select and rubric controls and keep role-specific validation. [ADM-01](findings.md#adm-01), [GRD-02](findings.md#grd-02). |
| Tables and lists | Admin record cards, Student assignment cards and the grading submission rail have different row and action density. The inventory finds a Table primitive outside today’s routed import graph. | Preserve action, data and reading-order requirements. The presence of Table alone supplies no migration decision. [Component inventory](component-inventory.md#inventory-without-a-traced-page-import). |
| Badges and status | Badge supplies a common shape and base variants. Assignment statuses, lesson states and skill legends have local mappings. A schedule skill color and an assignment-list skill color can differ despite the same label. | Review meaning and contrast by task before standardizing. [D-03](design-decisions.md#d-03), [Student assignment listing](../../src/app/assignments/page.tsx), [calendar legend](../../src/components/extension/schedule-tab.tsx#L119). |
| Notifications and feedback | Portal headers share a bell and Sonner is mounted at the root. Persistent alerts, inline errors and toast appear in different task states. | Give active notifications the right names and preserve existing read behavior. Approve a policy for persistent versus transient feedback before shared normalization. [D-06](design-decisions.md#d-06). |
| Loading and empty states | Portal guard uses a spinner, pages use skeletons or feature loaders. Course, grading and notification empty states have task-specific language. WIP routes have an explicit separate presentation. | Give feedback a readable state when evidenced, starting with callback. Keep semantics of empty, unavailable and WIP distinct. [AUTH-03](findings.md#auth-03), [WIP owner](../../src/components/custom-ui/work-in-progress.tsx). |

## Intentional specialized layouts

The exam owns its sticky task header, section navigation and bottom controls because timing and submission are part of the task. The grade workspace keeps submission selection, response and scoring in one view. Builder keeps library, canvas and the inspector together at widths that can support it. The measured barriers concern available inline width, control reachability and accessible names. The audit does not establish a reason to merge these compositions into a single dashboard layout. [Exam](audit/ielts-examination.md), [grading](audit/grading-ai-feedback.md), [builder](audit/assignment-builder.md).
